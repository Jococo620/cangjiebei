# 演示说明（现场演示 / 演示视频脚本）

本文档给出「鉴真」智能体的推荐演示路径，既可用于现场答辩，也可作为演示视频录制脚本。演示全程可在 **离线 / 内网** 环境完成（内置种子知识库与官方样本回放），不依赖外网 LLM 也可展示核心能力。

## 一、环境准备

1. 按根目录 `README.md` 的「快速开始」启动服务（`start.bat` 或 `python run.py`）。
2. 打开 `http://localhost:7800/frontend/dashboard/`。
3. 确认健康检查：`GET http://localhost:7800/health` 返回 `status: ok`。
4. 确认技能与知识库就绪：health 响应中 `skills`（SymPas 84 项）与 RAG `chunks`（约 3000 条）非零。

## 二、演示主线（建议 5 分钟）

### 1. 系统概览与架构讲解（约 1 分钟）

- 打开 Web 控制台，展示 SOC 风格界面：智能对话、安全分析、XDR 监测、系统设置四个模块。
- 用一句介绍：证据锚定 RAG + 可验证 CoT + ReAct 零干预闭环的安全运营超级智能体。

### 2. 智能对话与防幻觉（约 1.5 分钟）

- 在「智能对话」输入一条安全研判问题，例如：`CWE-78 命令注入的缓解措施是什么？`
- 强调回答是**流式输出**：先展示「正在调用安全分析工具 → 工具执行完成 → 生成分析报告」的过程感，回答逐字出现，体验与主流大模型对话一致。
- 展示回答末尾的**可点击引用卡片**（`[1][2]…`），点开展示证据片段与来源。
- 追问一个知识库未覆盖的冷门问题，展示系统**低置信拒答**（返回「知识库证据不足，拒绝臆测」）而非凭空编造——这是防幻觉的核心卖点。

### 3. 程序分析能力 + 漏洞闭环 + 仓颉引擎（约 2 分钟，重点）

> **这是技术含金量最高的一段，建议作为演示重点。** 一句话立论：CangSight 不是「套壳大模型问答」，而是把**程序分析（静态分析 + 程序切片 + 谱故障定位）**作为底层能力，让 LLM 的每一步判断都有可复现的代码证据支撑。

- 在「安全分析」触发漏洞闭环场景（`vuln_closed_loop`），展示 `code_scan → sympas_slice_table → sbfl_rank → agentic_repair → eval_patch_taint → plan_quality_gate` 六步链路。
- **逐层讲清程序分析的价值**：
  - `sympas_slice_table`（程序切片）—— 只保留与危险点（sink）相关的语句，把「漏洞是否可达」落到确定性的数据流/控制流分析上，而不是让模型猜。
  - `sbfl_rank`（基于谱的故障定位）—— 用测试覆盖谱给可疑语句排序，给出「哪一行最可能出问题」的量化依据。
  - `eval_patch_taint`（补丁污点评估）—— 修复后重新做污点传播，验证补丁是否真的堵住了漏洞，形成「检测 → 修复 → 复验」闭环。
- 强调 `sbfl_rank` 与 `sympas_slice_table` 来自本组自研 SymPas 工具，是**可离线、确定性的国产静态分析能力**，而非黑盒大模型。
- 展示仓颉语言 DAG 引擎：说明处置流程拓扑排序由 `cangjie_engine/`（Cangjie 语言编写，端口 2270）完成；可演示引擎关闭后系统自动回退 Python 实现（降级鲁棒性）。

### 4. HITL 人机协同 + EAT 审计（约 1 分钟）

- 触发一个高危处置动作（如 EDR 隔离 / 防火墙封禁），展示系统强制人工审批（HITL 网关）。
- 展示审计链：每一步决策与工具调用均留痕，可追溯（EAT / 哈希链签名）。

## 四、录制建议

- **分辨率**：1920×1080，画面完整包含浏览器地址栏与后端终端日志。
- **无外网方案**：配置 LLM 为任意本地/内网兼容接口；若无法联网，可切换到内置样本回放模式，展示确定性离线能力。
- **关键镜头**：防幻觉拒答、可点击引用卡片、仓颉引擎拓扑排序输出、HITL 审批弹窗、EAT 审计留痕。
